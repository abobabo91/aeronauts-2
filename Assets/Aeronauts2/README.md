# Aeronauts 2 assets

This is the root for all first-party game assets. Keep each asset in the domain folder that owns it and keep third-party packages under `Assets/ThirdParty`.

`Scripts` contains the fixed-tick Flight Lab duel vertical slice. Assets under `Settings/` own feel-sensitive flight, aim, input, weapon, shield/hull, target, and bot values. `AimCameraController` owns the gameplay Aim/Forward View state, while `AimTuning.asset` contains independently editable constrained and full-360 comparison profiles. `PlayerWeaponController` converts the centered camera target into primary/railgun paths from the generated frame's shared `HeadCockpitCombatOrigin`, including cover obstruction. `TargetState` and `TargetSimulation` own the data-only non-regenerating shield gate, part-specific hull damage, elimination, and respawn rules; `WeaponDamageProfile` makes shield, body, critical, and bypass behavior explicit. `CombatantHealth` binds those shared rules to player, bot, and target presentation, while `TargetDummy` remains a thin drill specialization. `BotFlightController` drives the shared `FlightSimulation.Step`; `BotWeaponController` fires the shared finite-speed primary using behavior from `BotTuning.asset`; `DuelMatchController` owns the first-to-five score; and `CombatDrillController` coordinates manual reset. `Editor/FlightLabSceneBuilder.cs` regenerates the greybox scene and its tuning/material assets; `Editor/Build/BuildPipeline.cs` produces the WebGL player. Both are development tooling, not runtime behavior. `Presentation/BrowserTelemetryReporter.cs` and `Plugins/WebGL/Aeronauts2Browser.jslib` provide the read-only state snapshot used by real-browser automation and compile to active behavior only for a WebGL player.
